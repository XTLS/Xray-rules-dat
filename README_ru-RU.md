# GeoIP

[English](./README.md) | [简体中文](./README_zh-Hans.md) | Русский | [فارسی](./README_fa-IR.md)

Этот репозиторий формирует данные GeoIP на основе IPInfo Lite. Он предоставляет исходную классификацию по странам и территориям, региональные наборы для разных условий маршрутизации и общие категории для Xray, sing-box, Clash и других приложений.

## Принципы

Полнота данных GeoIP напрямую влияет на маршрутизацию. При международной маршрутизации через несколько выходных узлов покрытие адресов MaxMind не соответствовало требованиям проекта. Поэтому в качестве основы для исходной классификации по странам и территориям используется IPInfo Lite, а anycast-адреса выделены в отдельную категорию, чтобы избежать неоптимальных маршрутов при выборе выхода по стране.

Страна назначения IP-адреса и потребности пользователя в маршрутизации — два разных вопроса. Классификация по странам отвечает на вопрос «К какой стране или территории относится этот IP-адрес назначения?». Пользователям в материковом Китае, Иране, России и других регионах также важно знать: «Находясь в этой стране или на этой территории, к каким адресам назначения следует применять определённую политику маршрутизации?». Одной лишь принадлежности адреса назначения к стране недостаточно, чтобы полностью описать такие потребности.

Поэтому проект вводит региональные наборы `in-*`, которые служат списками адресов для прямого подключения в соответствующих регионах. Наборы `in-cn`, `in-ir`, `in-ru` и другие составляются с учётом местных условий доступа и требований к маршрутизации. Например, адреса зарубежных сервисов, Telegram, Twitter или CDN могут включаться в набор, если из этого региона к ним можно подключаться напрямую и эффективно. При особых требованиях наборы также могут содержать частные адреса.

У исходной классификации по странам есть и самостоятельное применение. Например, при настройке выходных узлов в нескольких странах или территориях может потребоваться выбирать узел по стране IP-адреса назначения. Для этого следует использовать обычные коды стран, а наборы `in-*` — для маршрутизации с учётом текущего местоположения пользователя.

Таким образом, полная версия `geoip-full.dat` сохраняет оба вида данных: обычные коды стран соответствуют исходной классификации IPInfo Lite, а записи `in-*` содержат региональные наборы. Региональные дополнения не изменяют исходную классификацию по странам.

Облегчённая версия `geoip-lite.dat` не содержит полной классификации по странам и не подходит для выбора выходного узла по стране IP-адреса назначения. Сохранённые в ней обычные коды стран — лишь псевдонимы региональных наборов для совместимости с привычными для сообщества настройками.

Обе версии содержат данные IPv4 и IPv6.

## Региональные наборы

### Материковый Китай: `in-cn`

`in-cn` — список адресов для прямого подключения при маршрутизации из материкового Китая.

Для IPv4 объединяются следующие два источника:

- misakaio/chnroutes2
- china.txt из gaoyifan/china-operator-ip

Для IPv6 используется только china6.txt из gaoyifan/china-operator-ip.

Поскольку интернет-провайдеры материкового Китая ухудшают международную связность, зарубежные адреса фактически образуют чёрный список. Поэтому для материкового Китая поддерживается только список адресов для прямого подключения, без отдельного чёрного списка.

### Иран: `in-ir`

За основу взяты исходные данные IR IPv4 и IPv6 из IPInfo Lite. К ним добавляются адреса Eitaa (AS202798) и GAP (AS210877) из локальной базы ASN, списки адресов CDN ArvanCloud, DerakCloud, IranServer и ParsPack, а также шесть частных адресов, используемых отдельными местными сервисами в Иране. Данные ParsPack берутся из текстового зеркала Chocolate4U/Iran-v2ray-rules. Отдельный набор `blacklist-ir` содержит адреса, подставляемые при блокировках, и другие подставляемые адреса.

### Россия: `in-ru`

За основу взяты исходные данные RU IPv4 и IPv6 из IPInfo Lite, дополненные белым списком мобильного интернета hxehex/russia-mobile-internet-whitelist. Отдельный набор `blacklist-ru` объединяет списки IP-адресов Antifilter и 1andrevich/Re-filter-lists, а также префиксы Telegram из справочной конфигурации.

## Общие категории

Полная и облегчённая версии содержат следующие общие категории:

- `geoip:private`
- `geoip:cloudflare`
- `geoip:cloudfront`
- `geoip:facebook`
- `geoip:fastly`
- `geoip:google`
- `geoip:netflix`
- `geoip:telegram`
- `geoip:twitter`
- `geoip:tor`

`geoip:anycast` включён только в полную версию.

## Сборка

Поместите `./ipinfo/ipinfo_lite.mmdb` в корень репозитория и убедитесь, что каталоги `./tmp/geoip-in` и `./output` очищены. Затем выполните:

```sh
go run . convert -c config-geoip-in.json
go run . convert -c config-geoip-lite.json
go run . convert -c config-geoip-full.json
```

Первый шаг создаёт временные текстовые файлы региональных наборов и чёрных списков в `./tmp/geoip-in/`. Сборки lite и full читают эти файлы напрямую. После первого шага их можно выполнять независимо друг от друга или в любом порядке. Не очищайте каталоги между этими тремя шагами.

Сборка lite создаёт только `./output/geoip-lite.dat`. Сборка full создаёт `./output/geoip-full.dat`, а также отдельные файлы для каждой категории:

| Каталог вывода           | Формат                  |
| ------------------------ | ----------------------- |
| `output/dat/`            | Xray GeoIP DAT          |
| `output/srs/`            | sing-box SRS            |
| `output/mrs/`            | Mihomo MRS              |
| `output/text/`           | CIDR в текстовом виде   |
| `output/clash/classical/` | Clash classical RuleSet |
| `output/clash/ipcidr/`    | Clash ipcidr RuleSet    |

В командах сборки необходимо явно указывать файл конфигурации через `-c`. Дополнительные параметры описаны в [руководстве по настройке (на китайском языке)](./configuration.md).
